# 基本概念

FLYX 由一个 **面板** 和装在各台服务器上的 **节点 agent** 组成：面板负责配置和展示，agent 负责在服务器上执行。先弄清下面几个词，后面的文档会好读很多。

## 整体结构

```txt
客户端 ──► 中转机（前置 / IX）──► 落地机（运行 Xray / sing-box / Snell）──► 网站
             ▲                        ▲
             └──── 节点 agent ─────────┘
                        ▲
                     面板（Web 界面 + 后端）
```

| 名词 | 是什么 | 在面板哪里 |
|------|--------|-----------|
| 面板 | Web 界面和后端，用 Docker 部署在一台服务器上 | — |
| 节点 | 装了 agent、连上面板的服务器，可以当落地，也可以当中转 | **节点** 页 |
| 内核 | 落地机上真正跑代理协议的程序：Xray、sing-box 或 Snell | **落地 → 内核** |
| 入站 | 内核上的一个代理服务（协议 + 端口 + 凭据），客户端连的就是它 | **落地 → 入站** |
| 导入的节点 | 不是面板搭的现成节点（脚本搭的、机场的），只用来接中转、进订阅 | **落地 → 导入** |
| 隧道 | 从入口节点到出口节点的转发线路 | **中转 → 隧道** |
| 中转线路 | 把某条隧道接到某个落地上，客户端先连中转再到落地 | **中转 → 线路** |
| 转发规则 | 传统的端口转发：入口端口收到的流量转到目标地址 | **规则** 页 |
| 订阅 | 一个链接，包含选中的落地和它们的中转线路，客户端导入即用 | **订阅** 页 |

## 落地和中转

- **落地**：客户端最终连到的节点，网站看到的是落地的 IP。可以在自己的服务器上搭（装内核、建入站），也可以导入现成的节点
- **中转**：客户端和落地之间的跳板，用来改善线路（比如国内前置 → IX → 海外落地），本身不跑代理协议，只转发流量

一台服务器可以同时当落地和中转。

## 一条线路怎么搭起来

1. [安装面板](./install.md)，在 **设置** 里填好“面板后端地址”
2. [安装节点](./agent.md)：在落地机和中转机上运行面板生成的安装命令
3. [搭建落地](./nodes.md)：给落地机装内核、建入站
4. [对接中转](./relay.md)（可选）：建隧道，把它接到落地上
5. [订阅](./subscription.md)：把落地和中转线路一起导入客户端

照着做一遍见 [快速上手](./getting-started.md)。
