# 延迟与回程

面板可以让每台节点定时测到国内各地运营商的延迟和丢包，并检测回程走的是哪条线路（CN2 GIA、163、9929、4837、CMI、CMIN2），结果显示在节点列表和卡片上。

## 原理

- **延迟**：节点每 1 分钟向每个 **测试点** 发 4 次 TCP 连接，记录平均延迟和丢包。测试点是放在各地运营商机房里的地址，所以测出来的就是“该地区这家运营商的用户到节点”的延迟，比从面板服务器测准确得多
- **回程**：节点对每个测试点做一次路由追踪，按经过的骨干网判断线路，每天自动检测一次

不设置测试点时，节点不测延迟；导入的节点在落地页显示面板服务器到它的延迟，只能作为参考。

经中转的线路（前置 → IX → 落地）也有估算的端到端延迟，见 [对接中转 - 延迟](./relay.md#延迟)。

## 设置测试点

**设置 → 延迟测试点**：

1. 点 **添加三网推荐** 一键加上广东电信、上海联通、北京移动；或点 **添加预设** 从北京 / 上海 / 广东 × 电信 / 联通 / 移动里挑；也可以 **自定义** 任意域名或 IP 和端口
2. **默认**：打开的测试点所有节点都测（单独设置过的节点除外）
3. **卡片显示**：最多勾 3 个，卡片上固定显示它们；一个都不勾时显示最差和最好的
4. 保存后所有节点马上重测一遍

最多 30 个测试点。改名会自动同步到单独设置过的节点。

## 给节点单独设置

不同节点面向的用户不一样（比如有的只卖移动），可以给节点单独选测试点：

- **单个**：**节点** 页点节点的 **测试点**
- **批量**：**节点** 页点 **多选**，勾选节点后点 **测试点**，保存会覆盖这些节点原来的设置

选 **跟随默认** 就测 **设置** 里打开“默认”的测试点，那边改了这里跟着变；选 **自定义** 自己勾选，也可以指定这台节点卡片上固定显示哪几个。一个都不勾就是这台节点不测延迟和回程，卡片上显示“不测延迟”。

## 看结果

延迟和回程显示在 **节点** 页的节点列表和卡片上；**落地** 页只给导入的节点显示面板测的延迟，自建入站只显示能不能连上（线路看它所在的节点）：

| 颜色 | 含义 |
|------|------|
| 绿 | 低于 100 ms，没有丢包 |
| 黄 | 100–300 ms，或有丢包 |
| 红 | 300 ms 以上、丢包 50% 以上，或连不上 |

每个测试点下面一行是它的回程线路。点延迟打开 **延迟详情**，列出到每个测试点的延迟、丢包和回程，底部有四个按钮：

- **重测**：马上测一次
- **趋势**：延迟趋势图
- **回程**：回程路由详情
- **测试点**：给这台节点单独选测试点

## 延迟趋势

点 **趋势**，可以看最近 1 小时、6 小时、24 小时、7 天或 30 天里到每个测试点的延迟曲线，以及分位数和异常摘要，适合看晚高峰是否拥堵。

实际采集周期为 1 分钟，页面每 60 秒自动刷新。**数据粒度** 的“1 分钟 / 5 分钟”只控制已有采样的汇总方式；“默认”会按时间范围自动合并采样。网络质量采集独立运行，一轮完成后才会开始下一轮，超时或排队可能使实际完成时间略有波动。

历史数据按 **设置 → 节点与监控 → 监控数据保留天数** 自动清理。

## 回程线路

点 **回程** 查看到每个测试点经过的每一跳和识别出的线路，点 **重新检测** 马上测一次。识别规则：

| 线路 | 依据 |
|------|------|
| 电信 CN2 GIA | 经过 59.43 段，不经过 202.97 |
| 电信 CN2 GT | 经过 59.43 段，也经过 202.97 |
| 电信 163 | 经过 202.97 |
| 联通 9929 | 经过 218.105 / 210.51 |
| 联通 4837 | 经过 219.158 |
| 移动 CMIN2 | 经过 223.118–223.121，且归属 AS58807 |
| 移动 CMI | 经过 223.118–223.121 |

IPv6 没有专门的骨干网段，按每一跳的归属网络识别：AS4809 为 CN2（之前没经过电信 AS4134 即 GIA，经过即 GT），AS4134 为电信 163，AS9929 / AS4837 为联通，AS58453 / AS58807 为移动 CMI / CMIN2。

- 双栈节点（有 IPv4 也有 IPv6）对有 IPv6 地址的测试点两条都测：回程详情里每个测试点分 IPv4、IPv6 两行，卡片上显示 IPv4 线路，IPv6 走的不一样时后面多一个小标签（例如“CN2 GT v6 CN2 GIA”）；IPv6 线路变化也会提醒。需要节点 agent 3.3.28 及以上
- 节点没有 IPv4、或测试点只有 IPv6 地址时自动改用 IPv6 检测，结果旁标 **IPv6**；只有 IPv6 的节点要选有 IPv6 地址的测试点（域名有 AAAA 记录，或直接填 IPv6 地址）。IPv6 回程需要节点 agent 3.3.27 及以上
- 回程每天自动检测一次，失败的 6 小时后重试；测试点改了，或节点 agent 升级后会马上重新检测
- 需要节点以 root 运行（或有 NET_RAW 权限），节点 agent 过旧时会提示升级，见 [升级](./upgrade.md#节点-agent-升级)
- 目标不回应时只显示到最后一个有回应的路由器；没经过上面的骨干网显示“未识别”

## 告警

在 [通知](./notify.md) 里勾选：

- **延迟 / 丢包异常**：某个测试点连续 3 次（约 3 分钟）丢包超过阈值（默认 20%），或延迟超过阈值（可选，默认不按延迟提醒），恢复时也会通知
- **回程线路变化**：每天检测回程时对比上一次，例如 CN2 GIA 变成 163

## 连通性检测

和测试点无关，面板服务器每 3 分钟会连一次落地页上的所有节点，包括导入的节点和面板搭建的入站，看端口能不能连上。落地页上方 **更多 → 检测节点连通性** 可以马上测一遍：

- 连得上：自建入站显示“可连接”，导入的节点显示面板到它的延迟
- 连不上：红点，并显示原因（连接超时、域名解析失败、无法连接）

面板搭建的入站按 **分享地址** 检测，没填分享地址时用节点的服务器 IP。内核在跑但连不上，通常是云服务商的安全组或防火墙没有放行这个端口。节点离线或内核没在运行时不检测，只显示节点或内核的状态（这两种情况本来就有各自的提醒）。

检测是从 **面板服务器** 发起的 TCP 连接，只能作为参考：面板连不上不代表中转机或客户端也连不上，反之亦然。以下几种不检测，不显示状态：

- Hysteria2、TUIC：只用 UDP，无法这样检测
- 开启了“仅允许中转机访问（防火墙白名单）”的入站：面板服务器不在白名单里，必然连不上
- 只监听本机（127.0.0.1）的入站

面板服务器没有 IPv6 时（常见于 Docker 部署），连不了只有 IPv6 的节点。这种情况不算连不上，也不发提醒：面板搭建的入站改由所在节点自己连一下这个地址和端口，显示“节点自检（面板没有 IPv6）”；节点自检只能确认内核在这个地址上监听，确认不了云服务商的防火墙有没有放行。导入的节点没有 agent，这种情况下不检测。

开启 [通知](./notify.md) 后，节点连续两次连不上会推送提醒。
