# 导入节点

在 **落地** 页点击 **导入**，可以把不是面板部署的节点（脚本搭的、没装 agent 的机器、机场节点）加进来，用来对接中转和加入订阅。转换规则参考 Sub-Store：所有格式先转成 Mihomo（Clash Meta）节点格式保存，再按订阅格式输出，参数不会丢失。

## 支持的输入

- 分享链接（每行一个）：`ss://`（含 obfs / v2ray-plugin / shadow-tls 插件）、`vmess://`（v2rayN 格式）、`vless://`（含 Reality、WS、gRPC、H2、XHTTP）、`trojan://`、`hysteria2://` / `hy2://`、`tuic://`、`anytls://`、`socks5://`
- base64 订阅内容
- Clash / Mihomo 配置（读取 `proxies`）
- sing-box 配置（读取 `outbounds`）
- Surge / Loon 节点行，例如 `名称 = snell, 1.2.3.4, 6160, psk=..., version=4`
- 订阅地址（`https://...`）：面板服务器会以 Mihomo 的身份去下载，拿到的通常是参数最完整的 Clash 配置。打开 **定时同步**（默认打开）会存成 [订阅源](./subscription.md#订阅源)，按时更新；关掉则只导入一次

## 说明

- 暂不支持 WireGuard、SSR、Hysteria v1 等类型，导入时会逐条提示
- 经中转连接时，原节点用域名连接的，会自动把域名保留为 TLS SNI 和 WebSocket Host；Hysteria2 端口跳跃只在直连线路上保留
- 面板不会部署、修改这些节点，也没有流量统计、白名单、换密钥等功能
- 原节点的地址或参数变了，点击该节点 → **编辑**，修改地址或粘贴新的链接替换参数，相关中转会自动指向新地址
- 勾选“订阅里只保留中转线路”后，订阅和分享中不再包含直连线路（该节点没有中转时就不会出现在订阅里）
- 删除只会删除面板里的记录和相关中转，不影响原服务器
- 同一个地址和端口不会重复导入

## 连通性检测

面板服务器每 3 分钟会连一次落地页上的所有节点，包括导入的节点和面板搭建的入站。落地页上方 **更多 → 检测节点连通性** 可以马上测一遍：

- 连得上：绿点，后面显示延迟（例如 `· 85 ms`）
- 连不上：红点，并显示原因（连接超时、域名解析失败、无法连接）

面板搭建的入站按 **分享地址** 检测，没填分享地址时用节点的服务器 IP。内核在跑但连不上，通常是云服务商的安全组或防火墙没有放行这个端口。节点离线或内核没在运行时不检测，只显示节点或内核的状态（这两种情况本来就有各自的提醒）。

检测是从 **面板服务器** 发起的 TCP 连接，只能作为参考：面板连不上不代表中转机或客户端也连不上，反之亦然。以下几种不检测，不显示状态：

- Hysteria2、TUIC：只用 UDP，无法这样检测
- 开启了“仅允许中转机访问（防火墙白名单）”的入站：面板服务器不在白名单里，必然连不上
- 只监听本机（127.0.0.1）的入站

开启 [通知](./notify.md) 后，节点连续两次连不上会推送提醒。

## 对接中转

导入后的节点和面板部署的入站一样：点击节点 → **中转** → 选择隧道即可，端口转发和隧道转发（包括经 IX 的多跳）都可以用。见 [对接中转](./relay.md)。
