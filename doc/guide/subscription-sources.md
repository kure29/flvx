# 来源与订阅源

订阅的“节点”页先选 **来源**：这个订阅包含哪些落地。机场或别人的订阅可以先添加成 **订阅源**，再当作来源选进来。

## 来源

- **全部落地**：包括以后新增的落地，不用再回来勾选
- **指定落地**：只勾选需要的，分“自建”“导入”和“订阅源”三组。订阅源按整个源勾选，以后更新进来的节点会自动跟上；只要其中一部分可以用下面的过滤

落地的中转线路会跟着它一起出现在订阅里。

## 订阅源

在 **落地 → 订阅源** 添加机场或别人的订阅链接，相当于 Sub-Store 的远程订阅；拿不到链接时也可以 **上传订阅文件**。也可以在 **落地 → 导入** 里粘贴订阅地址或选择文件，打开 **定时同步** / **存为订阅源**（默认打开）就会存成订阅源；关掉则只导入一次：

- 添加后立即拉取一次，节点出现在 **落地** 页“订阅源 · 名称”分组里，可以和其他导入节点一样检测、接中转、放进订阅
- **自动更新**：手动 / 6 小时 / 12 小时 / 每天。也可以点卡片右边的按钮立即更新
- **上传文件**：支持 Base64 订阅、分享链接、Clash / Mihomo 配置、sing-box 配置、Surge / Loon 节点行，最大 5MB。文件源不会自动更新，点卡片右边的上传按钮重新选文件即可，节点按下面的规则对上
- 更新时按 **名称** 对上已有节点（名称变了再按地址对）：地址变了就跟着改，挂在上面的中转也会改到新地址；订阅里没有了就删除，但挂着中转的会保留，免得中转断掉
- 拉取失败或返回空内容时保留现有节点，卡片上显示错误
- 机场返回的流量和到期信息（`Subscription-Userinfo`）会显示在卡片上
- **用途**：普通节点 / 中转（前置）/ 落地。机场节点通常拿来做前置：设成 **中转** 后，新建订阅会自动打开 [链式代理](./subscription-rules.md#链式代理)，整个源作为中转、自建节点作为落地，机场节点改名、增删都会自动跟上
- **只通过我的转发访问**：新加进来的节点不直接进订阅，只通过你自己机器上的转发（中转线路）连接
- 删除订阅源时可以选连同节点一起删除，或只删订阅源、节点留下变成普通的导入节点

典型用法：订阅选“指定落地”，勾上自己的落地和机场订阅源，再 [筛选地区、加国旗和排序](./subscription-nodes.md)，一个链接全搞定。
